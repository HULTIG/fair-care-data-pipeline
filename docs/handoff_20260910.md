# FareCare implementation handoff

Date: 2026-09-10

## Current state

The evaluation contract, source-first split, train-only transformation flow, aligned mitigation weighting, dataset validation, anonymization checks, orchestration controls, experiment runners, and server-pilot validation are implemented. The manuscript has not been regenerated. Numerical claims in `paper/v2/latex/main.tex` must remain unchanged until the validated result build is reviewed.

The working tree was based on `main`, with the pre-existing local artifacts preserved. The implementation was tested in the local virtual environment.

## Implemented changes

- Added a shared held-out evaluation contract under `src/pace/evaluation/`.
- Added one stratified 70/30 source split per dataset/seed, persisted membership hashes, and server-side held-out prediction artifacts.
- Added fit/apply anonymization boundaries so structural suppression is enforced only on the released training artifact.
- Added stable source identities, aligned training weights, estimator `sample_weight` consumption, and fit provenance.
- Unified dataset definitions in `configs/default.yaml` and added predictor, label, missing-value, and group validation.
- Added internal record IDs, train-only preprocessing behavior, explicit unavailable metrics, and corrected utility-retention semantics.
- Repaired anonymization validation, release postconditions, sensitive-attribute handling, and numeric-noise naming.
- Added stage status, failure artifacts, run IDs, seed propagation, eligibility checks, stale-artifact protection, and Spark cleanup in orchestration.
- Updated experiment runners to use ROC AUC, nullable unsupported metrics, shared configuration behavior, and active-parameter sensitivity sweeps.
- Added protocol, freeze, pilot, and validated-results documentation.

## Validation completed

The full test suite passed: **81 tests passed**. Python compilation and `git diff --check` also passed. An isolated end-to-end COMPAS orchestration smoke run also passed with 2,165 held-out records evaluated against the persisted split.

The fresh server pilot completed and passed strict validation:

- 4 datasets × 5 configurations = 20 successful runs.
- Pilot manifest: `results/revised/server-pilot/pilot-20260910T163849Z-seed42/manifest.json`.
- Validated manifest: `results/revised/validated-server-pilot-manifest.json`.
- Traceable aggregate: `results/revised/server-pilot-results.csv`.

The experiment outputs are:

- `results/revised/exp1.csv`: 20 configuration runs.
- `results/revised/exp2.csv`: 13 successful mechanism runs.
- `results/revised/exp3.csv`: 12 regulatory runs.
- `results/revised/exp4_robustness.json`: 10 robustness runs summarized by two configurations.
- `results/revised/exp5_kanonymity.json`: 3 k-anonymity sensitivity runs.
- `results/revised/exp5_numeric_noise.json`: 3 numeric-noise sensitivity runs.

Three Experiment 2 l-diversity configurations produced explicit empty-release failures and were withheld from the CSV: COMPAS, Adult, and NIJ. Their failure artifacts are under `results/exp2/*_ldiversity/*/failure.json`. These results must not be silently treated as successful or included in a complete aggregate.

Warnings observed during Spark runs include large task sizes, sklearn convergence warnings on Adult, and DoWhy graph/compatibility warnings. They were recorded as run observations; they do not establish causal validity or a formal privacy guarantee.
